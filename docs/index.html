DESIGN PROTOTYPE — 12 · 単元を開いて内訳

まるつけ個別指導の採点記録

1コマ最大2名の個別指導で、講師がスマホを片手に持ったまま ○ / × / − を打ち込む道具です。 連続採点は1タップ、生徒を替えるときだけ2タップ。集計と復習リストは記録から自動的に導出します。

これは動くプロトタイプです。 ○ × − を押すと実際に記録が積まれ、復習リストと分析にも反映されます。 × を押すと、続けてつまずきの分類（できる／あいまい／知識なし）を聞かれます。 復習リストの「解き直す」を押すと、その問題を入れた状態で記録画面に戻ります。 スマホで開くと実寸で確認できます。

2人は別の教材を進めています。生徒を切り替えると、教材・ページ・見出しがまとめてその生徒のものに入れ替わります。 鈴木さんの復習リストには p.31 の 練習問題2(3) が残り、番号がまったく同じ 確認問題2(3) は正解済みなので外れています。

        DESIGN DECISIONS

        迷ったところと、どちらに倒したか

        NAVIGATION

        ナビゲーションを上に置き、画面下部を丸ごと採点パッドに明け渡した

        タブバーは下部に置くのが定石ですが、この道具で最も頻度が高い操作は画面移動ではなく採点です。授業中の移動はほぼゼロ、採点は1コマで数十回。

        結果：親指が最も届きやすい下端を ○ × − が独占します。移動は稀なので、上端まで指を伸ばす代償は支払う価値があります。

        IDENTITY

        問題を特定するのは 教材＋ページ＋見出し＋大問＋小問

        同じ p.78 に 1(1) と 2(1) が並び、番号がまったく同じで見出しだけが違う組も出ます。さらに教材が違えば、同じ p.31 でも中身は無関係です。どこかを削ると、別々の問題が同じ記録として潰れます。

        結果：5つで1つの問題を指します。鈴木さんの p.31 は 確認問題2(3) が ○、練習問題2(3) が ×。復習リストには 練習問題2(3) だけが残ります。

        SESSION

        教材も生徒ごと。ページ番号は教材の中でしか意味を持たない

        同じコマの2人が別の教材を進めます。教材を共有状態にすると、生徒を替えるたびに選び直すうえ、ページ番号だけが残って別の教材の位置を指してしまいます。

        結果：教材は作業位置の一部として生徒ごとに持ちます。生徒を切り替えると、教材・ページ・見出しの選択肢がまとめてその生徒のものに入れ替わります。

        HONESTY

        単元名は教材の語彙。同じ名前でも教材をまたいで合算しない

        2冊とも「式の計算」という単元を持っていますが、中学2年と3年では範囲も難度も違います。名前が一致するからといって足し合わせると、正答率が意味のない数字になります。

        結果：分析は教材ごとに区切って並べ、どの教材の単元かを必ず添えます。復習リストでも、その生徒が2冊以上使っているときだけ教材名を出します（1冊しか使っていなければ、出しても情報量がゼロなので出しません）。

        IDENTITY

        見出しと番号は別のフィールド。混ぜると語彙が破裂する

        「基本問題1」をひとつの文字列として持つと、基本問題1・基本問題2・基本問題3… を全部別々に登録することになり、選択肢が際限なく増えます。見出しは有限の語彙、番号は無限の連番で、性質が違います。

        結果：見出しは教材ごとの語彙（数個）、大問番号は連番として別に持ちます。見出しが増えてもチップは増えません。

        INPUT

        自由記述にしても、授業中に文字は打たせない

        見出しを自由入力にすると柔軟にはなりますが、毎回キーボードを開くようでは採点の速度が死にます。一方で、見出しの語彙は教材ごとに数個しかなく、ほとんど変わりません。

        結果：入力するのは初回だけ。一度追加した見出しはチップとして並び、以後はタップで選べます。溜まった語彙は教材画面で確認できます。見出しのない教材は「なし」を選んだままにします。

        INPUT

        見出しは選択式、番号はステッパー。切り替わる頻度が違うから

        見出しは「基本問題をひととおり終えてから練習問題へ」で、めったに動きません。番号は1問ごとに進みます。同じ形の操作にするのは、この差を無視することになります。

        結果：見出しはチップ、大問と小問は − ＋ のステッパーを1行に並べました。フィールドが1つ増えても採点パッドの高さは変わっていません。

        INPUT

        ページを送っても見出しは残す。番号だけ戻す

        見出しは複数ページにまたがりますが、大問番号はページごとに振り直されるのが普通です。3つとも一律にリセットすると、ページを送るたびに見出しを選び直すことになります。

        結果：ページ送り → 大問と小問が 1(1) に戻り、見出しは維持。見出しの切り替え → 番号が 1(1) に戻る。大問を送る → 小問が (1) に戻る。上位を動かしたときだけ下位が戻ります。

        INPUT

        生徒は固定、小問だけが自動で進む

        1対2の実際の動きは「一人の答案をまとめて見る」です。記録のたびに生徒が切り替わる設計にすると、毎回選び直すことになります。

        結果：採点後も選択中の生徒・見出し・大問は動かず、小問だけ +1 されます。連続採点は ○ を連打するだけで済みます。

        SESSION

        定員2名。作業位置は生徒ごとに持ち、戻れば続きから再開する

        1対2は交互に見て回る仕事です。片方を採点している間、もう一人は別のページの別の問題を解いています。ページや番号を2人で共有すると、生徒を替えるたびに位置を入れ直すことになります。

        結果：教材・ページ・見出し・大問・小問は生徒ごとに保持します。田中さんを ○ で3問進めてから鈴木さんに移っても、鈴木さんは離れたときの続きから始まります。

        SESSION

        2名になった余白を、相手の現在位置に使う

        定員が2名に決まったことで、生徒ボタンは2つで済むようになりました。空いた幅を大きなボタンにするだけでは、情報は増えません。

        結果：各ボタンに「その生徒が今どこを解いているか」と本日の件数を出しました。切り替える前に相手の進み具合が見えるので、どちらを先に見るかの判断がその場でできます。

        ERROR RECOVERY

        確認ダイアログを置かず、取り消しで受け止める

        1回の入力あたりの重みが軽いので、毎回「よろしいですか」を挟むと道具として使い物になりません。かといって誤タップは必ず起きます。

        結果：記録は即座に確定し、直後にトーストで「取り消す」を出します。速度を落とさずに誤りを回収できます。

        DATA MODEL

        単元はページから引く。記録には持たせない

        記録時に単元を選ばせるとタップが1回増え、しかも選び間違えが混ざります。ページ番号は答案を見れば必ず分かる確実な情報です。

        結果：その教材のページ範囲から単元を自動判定して表示だけします。あとから単元の区切りを直せば、過去の集計も一緒に直ります。

        REVIEW LIST

        「卒業」フラグを持たず、最新の結果から毎回導出する

        同じ(生徒・教材・ページ・見出し・大問・小問)の最新レコードが × なら「間違えた問題」、− なら「未実施」、○ なら両方から外れる。それだけの規則です。

        復習リストの「解き直す」は、教材ごと呼び出します。別の生徒の復習から入っても、その生徒・その教材の状態に切り替わります。

        結果：過去の × は消えずに全部残り、正答率の計算にも使われます。状態の持ち方を間違えて不整合が出る余地がありません。

        DATA MODEL

        未実施は成績ではないので、正答率の母数から外す

        ○ と × は結果、− は「そもそも解いていない」です。3つを同じ分母で割ると、時間切れで飛ばした問題が増えるほど正答率が下がり、できるようになったのか手をつけていないだけなのか読めなくなります。

        結果：正答率は ○ ÷ (○ + ×)。未実施は件数として別に出します（50% n=8 未実施2）。構成比の棒には未実施も入りますが、彩度のない灰色を薄く敷いて「データが無い部分」として読ませます。棒の並べ替えも、実施した問題が3問に満たない単元は下に落とします。

        INPUT

        つまずきの分類は、× を押した直後に聞く

        「なぜ間違えたか」が分かっているのは、答案を見ているその瞬間だけです。あとでまとめて分類しようとすると、記憶を頼りに推測することになります。

        結果：× のときだけ、取り消しトーストに できる あいまい 知識なし の3つが出ます。押さなければ「分類なし」のまま進むので、採点の速度は落ちません。あとから記録の行をタップして付け直すこともできます。

        ACCESSIBILITY

        黄・緑・赤は指定どおり。ただし色だけには意味を持たせない

        ご指定の3色を測ったところ、緑と赤はP型・D型色覚で ΔE 2.6（基準8、下限6）。色相を最大限離しても 4.5 で、色だけでは区別できません。これは ○ を緑から藍青に移したのと同じ問題です。

        結果：色はご指定のまま使い、必ず文字と組にしました。分類チップは色玉＋語、内訳グラフの凡例は各色に「知識なし 3」と件数まで添え、緑の帯には45°のハッチを敷いています。色が読めなくても内訳が読めます。

        ANALYSIS

        内訳は単元の中にしまい、押したときだけ開く

        つまずきの内訳を独立したブロックとして並べると、単元別の棒と同じ単元名が二度出てきます。同じものを二か所で探すことになり、画面も倍の長さになります。

        結果：単元の行そのものを開くようにしました。× のある単元にだけ矢印が付き、押すとその単元の内訳・凡例・該当する問題の一覧が下に開きます。中身が無い単元は矢印も出さず、押せません。日付別の行と同じ操作なので、覚えることは増えていません。

        開いた一覧からも分類を付け直せます。同じ問題を別の日に何度も間違えている場合は行が複数出るので、日付を添えて区別しています。

        REVIEW LIST

        「間違えた問題」と「未実施」を混ぜない

        どちらも残っている問題ですが、講師が取る行動が違います。間違えた問題は解き直させる、未実施はまず解かせる。一列に混ぜると、優先順位を毎回自分で判断し直すことになります。

        結果：復習リストを2つの見出しに分け、ボタンの文言も「解き直す」「解く」で変えました。上部の集計も 間違えた／未実施／今週の卒業 の3つに分けています。

        ACCESSIBILITY

        ○ を緑から藍青に変えた — 緑と紅は色覚特性で区別できない

        3分類になって ○ と × が棒グラフで隣り合うようになりました。この2色を検証したところ、P型・D型色覚での差は ΔE 2.1（基準は8以上）。事実上同じ色です。これまでは間に琥珀色の △ があり、緑と紅が隣接していなかったため露見していませんでした。

        結果：○ を藍青に移して ΔE 10.7 まで離しました。塾では青ペン＝できた／赤ペン＝間違いの方がむしろ一般的なので、意味の面でも無理がありません。未実施の灰色は彩度を持たない「不在」の色として、意味色とは別枠で扱っています。

        ANALYSIS

        単元別と日付別は別の問いなので、軸として分ける

        単元別が答えるのは「何が苦手か」、日付別が答えるのは「あの日は何をやって、どうだったか」です。同じ画面に積むと縦に長くなるうえ、どちらを見ているのか分からなくなります。

        結果：生徒セレクタの下に軸のタブを置きました。生徒を選ぶピルとは形を変えて（塗り／下線）、別種の選択であることを見た目で示しています。週ごとの推移は時間軸の話なので、日付別の側に移しました。

        ANALYSIS

        授業日は記録から導出する。日付の一覧を別に持たない

        「授業日」というテーブルを作ると、記録のない日が残ったり、記録した日が一覧に無かったりと、実態とずれていきます。

        結果：記録の日付でまとめるだけです。記録があった日だけが並び、今日採点すれば今日の行がその場で増えます。

        各行には、その日に使ったテキストと単元を出します。「あの日は何をやったか」は開かずに読めるべき情報だからです。1日に複数の単元・複数のテキストに触れていれば、テキストごとにまとめて並べます（新中問 数3 · 二次関数、平方根 / 必修テキ 数2 · 式の計算）。行を開くと、1問ずつの結果にもテキストと単元が付きます。

        HONESTY

        データ不足の単元を、正答率で並べない

        2問しか解いていない単元が「正答率 50%」で苦手の一位に来ると、判断を誤ります。

        結果：実施した問題が3問に満たない単元は薄く落とし、リストの下に「データ不足」として置きます。数字を出さないのではなく、信頼度を形で示します。未実施しかない単元は、正答率そのものを「—」にします。
