# まるつけ — バックエンド（GAS + スプレッドシート）

Google スプレッドシートをデータベースにし、Google Apps Script を Web API として公開する。
画面は GitHub Pages から配信し、この API を呼ぶ。

## 構成

```
GitHub Pages (公開)  ──fetch──▶  GAS Web App (匿名公開)  ──▶  スプレッドシート
   docs/index.html                  gas/*.gs                    シート7枚
```

## この構成の性質

**GAS のエンドポイントは匿名公開になる。URL を知れば誰でも叩ける。**
フロントは公開リポジトリにあるので、URL も、フロントに書いた合言葉も秘密にはできない。

したがって防御はパスワード認証だけに依存する。設計上そうしてある。

- `ping` と `login` 以外のすべての操作はトークンを要求する
- トークンが無効・期限切れなら即座に弾く
- ログイン失敗が15分に5回を超えると、そのログインIDを一時的にロックする
- パスワードは SHA-256 を1万回繰り返したハッシュで保存する（GAS に bcrypt が無いため）

**パスワードハッシュはスプレッドシート内にある。つまりスプレッドシートの共有範囲が、そのまま権限の範囲になる。**
シートを不用意に共有しないこと。「リンクを知っている全員」にはしないこと。

## セットアップ

### 1. スプレッドシートを作る

Google ドライブで新しいスプレッドシートを作り、分かる名前を付ける（例: `まるつけ データ`）。

### 2. スクリプトを送る

スプレッドシートのメニューから **拡張機能 → Apps Script**。ここで開いたプロジェクトに送る。

`clasp`（Google 公式のコマンドライン）で、`gas/` の中身をそのまま送れる。
エディタに手で貼るとエディタの自動補完でコードが壊れるので、こちらを使う。

```bash
npx @google/clasp@2.4.2 push --force
```

送られるのは7ファイル。`test/run.js` は `.claspignore` で除外している
（Node 用のテストで、読み込まれた時点で走り出すため）。

```
00_config.gs  10_sheet.gs  20_setup.gs  30_auth.gs
40_data.gs    50_api.gs    60_menu.gs   appsscript.json
```

初回だけ準備が要る。

1. [Apps Script API](https://script.google.com/home/usersettings) を**オン**にする
2. `npx @google/clasp@2.4.2 login` — ブラウザで承認する
3. リポジトリ直下に `.clasp.json` を置く（スクリプトIDが入るので Git には含めない）

```json
{ "scriptId": "スクリプトのID", "rootDir": "gas" }
```

スクリプトIDは、エディタの URL の `projects/` と `/edit` の間の文字列。

### 3. シートを作る

エディタ上部の関数リストから `initialize` を選んで実行。初回は権限の確認が出るので許可する。
（2回目以降は、スプレッドシートの **まるつけ → シートを作る** からでもよい）

シートが7枚できる。

| シート | 中身 |
|---|---|
| 講師 | ログインする人。パスワードハッシュもここ |
| 生徒 | |
| 教材 | |
| 単元 | 教材ごとのページ範囲 |
| 見出し | 教材ごとの語彙（基本問題・練習問題など） |
| 記録 | 採点1件が1行 |
| セッション | ログイン中の端末。手で触る必要はない |

### 4. 自分のアカウントを作る

**ここから先はスクリプトを触らない。** スプレッドシートを開き直すと、
上部のメニューに **「まるつけ」** が増えている。

**まるつけ → 講師を追加…** を選び、名前・ログインID・パスワード（8文字以上）を順に入れる。

講師を増やすときも、パスワードを変えるときも同じメニューから。

> パスワードはセルには入れない。入力した文字はハッシュに変換され、元の文字は保存されない。
> セルに一度書くと、消してもスプレッドシートの版履歴に残り続けるため。

### 5. 動作確認用のデータ（任意）

`seedSampleData` を実行すると、生徒2名と教材2冊が入る。実運用のシートでは実行しないこと。

### 6. Web アプリとして公開する

エディタ右上の **デプロイ → 新しいデプロイ**。

- 種類: **ウェブアプリ**
- 次のユーザーとして実行: **自分**
- アクセスできるユーザー: **全員**

「全員」にしないとフロントから呼べない。上に書いたとおり、これは想定どおりの構成で、
防御はパスワード認証が担う。

公開されると `https://script.google.com/macros/s/AKfy.../exec` という URL が出る。これをフロントに設定する。

### 7. 動作を確かめる

ブラウザでその URL を直接開くと「まるつけ API です。」と出れば公開できている。

### 8. 画面を API に繋ぐ

`docs/index.html` の先頭近くにある定数を書き換える。ここ1か所だけ。

```javascript
var API_URL = "";   // ← 6 で出た /exec の URL を貼る
```

貼ってコミットすると、GitHub Pages のページが**ログイン画面から始まる全画面のアプリ**に変わる。
デザイン資料の部分は自動的に畳まれる。

**空のままだとデモとして動く。** 記録はブラウザの中だけに積まれ、通信は一切しない。
URL を入れたあとでも、末尾に `?demo=1` を付ければデモとして開ける
（`https://……github.io/marutuke/?demo=1`）。人に見せるときはこちらを渡す。

> API_URL は秘密ではない。公開リポジトリに置く前提で設計してある。
> エンドポイントはもともと匿名公開で、防御はパスワード認証が担う。

#### 画面の作り

- ログインすると、その端末にトークンが残る（12時間）。毎回打ち直さなくてよい
- 続いて**そのコマの生徒を2名まで選ぶ**。選んだ生徒は、前回やめたところの次の問題から始まる
- 選んだ2名も端末に残る。授業中に誤って再読み込みしても選び直しにならない
- 上部の「交代」で次のコマの生徒に入れ替える。「ログアウト」でトークンを捨てる
- **採点は通信を待たない。** ○×− を押した瞬間に画面へ入り、送信は裏で走る。
  保存に失敗したときだけ、その1件を画面から取り消して赤い帯で知らせる
- トークンが切れたら自動でログイン画面に戻る

## コードを直したとき

**送るだけでは公開中の版は変わらない。** `push` はエディタの中身を差し替えるだけで、
公開されているのは「デプロイした時点の版」だから。2手要る。

```bash
node gas/test/run.js && npx @google/clasp@2.4.2 push --force
```

```bash
npx @google/clasp@2.4.2 deploy --deploymentId AKfycbwT55_v0LD3xK7yvY0cYVTUb7URmBurFeXonhpbA9C2FuaDfa-sNH__iKpamyIHB_g --description "更新の内容"
```

**`--deploymentId` を必ず付けること。** 付けないと新しいデプロイが作られ、URL が変わり、
`docs/index.html` の `API_URL` も直すはめになる。

画面でやるなら **デプロイ → デプロイを管理 → 鉛筆アイコン → バージョン「新バージョン」→ デプロイ**。
こちらも URL は変わらない。「新しいデプロイ」を選ぶと変わってしまう。

`clasp deployments` に出てくる `@HEAD` の方は GAS が自動で持っている試験用の枠で、
公開用ではない。触らなくてよい。

## API

すべて POST。本文は JSON だが `Content-Type` は `text/plain;charset=utf-8` で送る。
`application/json` にすると CORS の事前確認（OPTIONS）が飛び、GAS は応答できずに失敗する。

```
{ "action": "...", "token": "...", ... }
→ { "ok": true, "data": ... }  または  { "ok": false, "error": "..." }
```

| action | 認証 | 説明 |
|---|---|---|
| `ping` | 不要 | 疎通確認 |
| `login` | 不要 | `loginId`, `password` → `{token, teacher}` |
| `logout` | 要 | トークンを破棄 |
| `bootstrap` | 要 | マスタ＋記録を一括取得。`days` で期間指定（0で全期間） |
| `masters` | 要 | 生徒・教材・単元・見出し |
| `records` | 要 | `studentId`, `days` で絞り込み |
| `addRecord` | 要 | `student`,`book`,`page`,`section`,`major`,`q`,`result`,`cause` |
| `deleteRecord` | 要 | `id`。取り消し用 |
| `setCause` | 要 | `id`, `cause`(0〜3) |
| `addSection` | 要 | `bookId`, `label` |
| `addStudent` | 要 | `name`, `grade` |
| `addBook` | 要 | `title`,`short`,`subject`,`pages`,`units[]`,`sections[]` |

`result` は 1=○ 2=× 3=−、`cause` は 0=未分類 1=できる 2=あいまい 3=知識なし。
シート上では日本語で入る（手で読めるようにするため）。

## テスト

スプレッドシートと GAS の API を偽物に差し替えて、ロジックだけを手元で動かす。
Google 側の設定は一切要らない。

```bash
node gas/test/run.js
```

認証の強制（`login` と `ping` 以外の全操作がトークンを要求すること）、ロックアウト、
手でシートを壊したときの耐性などを確認している。`.gs` を直接読むのでコピーは不要。
**コードを直したら実行してからデプロイすること。**

## メニュー

スプレッドシート上部の「まるつけ」から。スクリプトエディタを開く必要はない。

| 項目 | すること |
|---|---|
| シートを作る | 足りないシートを作る。既にある物には触らない |
| 講師を追加… | 名前・ログインID・パスワードを聞いて講師を作る |
| パスワードを変更… | 変更したうえで、その講師の端末を全部ログアウトさせる |
| 手で足した行を整える | 下記 |
| 古いセッションを掃除 | 期限切れの行を消す |
| 全員をログアウトさせる | 端末を紛失したときなど |

### 生徒や教材をシートに直接足す

**生徒シートに名前を打つだけでよい。** そのあと **まるつけ → 手で足した行を整える** を実行すると、
空欄が埋まる。

- `id` が空 → 振る（これが無いと記録と結びつかない）
- `有効` が空 → TRUE にする
- `作成日時` が空 → 今
- 単元・見出しの `教材id` が空 → **`教材略称` から引く**（略称だけ打てば済む）
- 逆に `教材略称` が空 → `教材id` から埋める

直せないことは、実行後のダイアログで知らせる。

- パスワードが設定されていない講師（メニューから設定するまでログインできない）
- 教材と結びつかない単元・見出し（略称の綴り違い）
- ログインIDの重複

**講師を止めるときは、講師シートの `有効` を FALSE にする。** 行は消さない。
消すと、その人が付けた過去の記録から講師をたどれなくなる。生徒・教材も同じ。

## シートを手で編集するとき

**できること**

- 列の順番を入れ替える（列名で引いているので壊れない）
- 行を消す、値を直す
- 生徒・教材・単元・見出しの行を足す（足したあと「手で足した行を整える」を実行）
- 名前を直す（記録シートに残る昔の名前は変わらない。これは意図した動き）
- 記録シートの「結果」を ○ × − の範囲で書き換える
- 「つまずき」を できる / あいまい / 知識なし / 空欄 で書き換える

**やってはいけないこと**

- 見出し行（1行目）の文字を変える、列を消す
- `id` 列を書き換える
- 記録シートの「生徒id」「教材id」を、存在しない値にする

「生徒名」「教材略称」「講師名」の列は読むための控えで、システムは参照しない。
書き換えても集計は変わらない（逆に、生徒を改名しても過去の行は昔の名前のまま残る）。

## 制限と注意

- **ログインに1秒ほどかかる。** ハッシュを1万回繰り返しているため。総当たりを遅くする代償。
- **記録が増えると遅くなる。** 毎回シート全体を読むため。数万行までは実用範囲。
  超えたら年度ごとにシートを分けるか、別のデータベースへ移す。
- **GAS の実行時間は6分。** 通常の操作では届かない。
- パスワードハッシュはシート内にある。総当たりは遅くしてあるが、
  シートが漏れた場合の最後の砦はパスワードの長さになる。十分に長いものを設定すること。
